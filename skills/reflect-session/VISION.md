# reflect-session v1 — Vision

Снижение уровня непонимания между пользователем и нейронкой через анализ сессий.

Этот файл — целевая спецификация (что скилл должен решать и куда развивается). Операционная механика — в `SKILL.md`, аналитический метод — в `method.md`. При конфликте формулировок механика следует за этим файлом.

## Проблема

Нейронка не учитывает индивидуальные особенности пользователя: его формулировки, привычки ввода, особенности рабочей среды. Каждая сессия начинается «с нуля» — одни и те же недопонимания и ошибки среды повторяются. Наработки внутри сессии умирают вместе с ней.

## Ось общие/личные (v1.1)

Верхний уровень организации правил — **scope**, решается в Phase 3 ДО класса знаний:

- **Общие (G)** — «как Клоду работать в принципе». Универсальная дисциплина оркестратора, не зависящая от пользователя, машины и проектов. **Портируемо**: правило валидно в любой установке Claude Code. Живёт в `~/.claude/local-forks/_tracked/general-rules.md` (`@import` в `~/.claude/CLAUDE.md`), ID-префикс `g-`. Признак: правило не ссылается на этого юзера, его среду, пути, проекты, идиолект.
- **Личные** — всё, что привязано к этой установке: идиолект (K1), карта среды (K2), проектные подсказки и проектная дисциплина оркестратора (проектные K0). Живут в `~/.claude/CLAUDE.md` и его lazy-файлах, сохраняют внутреннюю структуру K1/K2/K0.

Решающий вопрос Phase 3: *сработает ли это правило у другого пользователя на другой машине без правок?* Да → общее (G). Нет → личное, дальше выбирается K-класс. При сомнении → личное (общий файл держим чистым; ошибочно-общее правило протечёт чужой контекст).

## Два класса знаний (выход скилла)

### К1 — Профиль взаимопонимания

Как этот пользователь формулирует запросы и что имеет в виду:

- **лексикон**: «фраза X = намерение Y» (пример: «остаётся там же» = implicit revert)
- **формат**: как отвечать, что раздражает, когда спрашивать vs делать
- **паттерны ввода**: триггерные слова, маркеры («именно» = verbatim)

### К2 — Карта среды

Что работает в окружении этого пользователя:

- **рецепты команд**: «в этой среде для X работает Y, не пробуй Z» (источник — сигнал B1: перебор из 5 команд → рабочая фиксируется)
- **особенности инструментов**: WSL/NTFS/rtk-ловушки
- **якоря**: пути, ID, версии, найденные перебором (сигнал B13)

Формат правила обоих классов: **Trigger / Action (Use) / Don't** + evidence-источник. К2-правила обязаны включать «Signal to recognise it» — признак, по которому агент узнаёт ситуацию до первой ошибки.

## Конвейер

1. **Decay-аудит** прошлых правил (validated / dormant / misfiring) — наработки не только копятся, но и чистятся (method.md Phase 0)
2. **Анализ сессии** по таксономии сигналов → наблюдения с evidence (Phase 1)
3. **Фильтр генерализуемости** — одноразовое не кодируется (Phase 2)
4. **Драфт правила** (К1 или К2) + adversarial self-test: counterfactual / conflict / specificity / minimality (Phases 4–5)
5. **Per-finding approval** — пользователь утверждает каждое правило отдельно (SKILL.md Step 4)
6. **Персистентность** — CLAUDE.md + git push; правило переживает машину и сессию (SKILL.md Steps 5–6)

## Триггер

- Ручной: `/reflect-session` после активной рабочей сессии
- **V1.1 (следующий шаг):** Stop-hook со счётчиком сигналов — после сессии с ≥N исправлениями пользователя напоминание «стоит прогнать reflect-session»

## Метрика успеха

Правило класса К1/К2, применённое в сессии N, в decay-аудите сессии N+k показывает `validated` (триггер встретился — ошибка не повторилась). Рост доли validated = снижение уровня непонимания. Повторная ошибка того же класса при существующем правиле = misfiring → правило дорабатывается.

## Вне скоупа V1

- Форки плагинов и генерация новых скиллов (категории B/C) — остаются в скилле, но не развиваются под эту цель
- Автоматический прогон без участия пользователя (mutation gate: правила в CLAUDE.md — мутации, требуют approval)
- Структурная реорганизация CLAUDE.md на отдельные файлы К1/К2 — кандидат на V2, когда объём правил это оправдает. **v1.1 сделал первый разрез по другой оси** — вынес общие (G) в `general-rules.md`, оставив личные K1/K2/K0 в `~/.claude/CLAUDE.md`.
